# AI-пайплайн: новая сущность

Цепочка для фичи вроде G-6 (отзывы и оценки ресторанов, `Review`). Стек — Java 25 + Spring Boot 3; ktlint/detekt нет, проверка — `./gradlew test`.

Rules (`.cursor/rules`) важнее скиллов, если они расходятся. Скиллы — в `.cursor/skills/`.

## Шаги

1. Задача       вход: тикет        → критерий «готово» сформулирован
2. Контекст     вход: кодовая база → контекстный пакет собран (@контракт, @образец, @entity, @тест)
3. План         вход: задача+контекст → план утверждён            [GATE]
4. Тесты (red)  вход: план         → тесты на поведение написаны, падают
5. Реализация   вход: тесты        → код под Rules, тесты зелёные (green)
6. Верификация  вход: код          → `./gradlew test` зелёный
7. Ревью        вход: дифф         → замечания разобраны            [GATE]
8. Рефакторинг  вход: зелёный код  → чистка без смены поведения (тесты держат)
9. PR           вход: финал        → осмысленный коммит и описание PR

| # | Шаг         | Инструмент                               | Вход           | Выход                                          | Gate |
|---|-------------|------------------------------------------|----------------|------------------------------------------------|------|
| 1 | Задача      | промпт + `docs/ai-prompts/feedback.md`   | тикет          | DoD, закрытые неоднозначности                  |      |
| 2 | Контекст    | `@` на rules и образцы                   | кодовая база   | пакет `@контракт` `@образец` `@entity` `@тест` |      |
| 3 | План        | режим Plan                               | задача + пакет | список файлов и инвариантов                    | да   |
| 4 | Тесты       | skill `unit-test`                        | план           | красные тесты                                  |      |
| 5 | Реализация  | skill `crud-endpoint` (тесты не трогать) | красные тесты  | зелёные тесты                                  |      |
| 6 | Верификация | `./gradlew test`                         | код            | сборка и тесты зелёные                         |      |
| 7 | Ревью       | skill `code-review` / Bugbot             | дифф           | блокеры закрыты                                | да   |
| 8 | Рефакторинг | skill `refactor-srp`                     | зелёный код    | чистый код, те же тесты                        |      |
| 9 | PR          | коммит + `gh pr create`                  | финал          | PR                                             |      |

Не перескакивать через gate. Шаг 5 не вызывать, пока 4 не красный. Шаг 8 — пока нет блокеров на шаге 7.

### 1. Задача

Сформулировать «готово» до кода. Неоднозначности закрыть вопросами, не догадками в реализации.

**Промпт**

```text
Тикет: <ID и формулировка>.
Сформулируй критерий «готово» (API, инварианты, роли USER/ADMIN, миграция, тесты).
Задай 3–5 вопросов по неоднозначностям. Код не писать.
```

**Пример (G-6 Review)**

Готово, когда:

- USER: `POST/PUT/GET /user/reviews`, список по ресторану с `page`/`size`
- ADMIN: `GET` + `DELETE /admin/reviews`
- поля: `rating` 1–5, опциональный `text` ≤ 1000, `date`, `user`, `restaurant`
- один отзыв на пару user+restaurant
- в карточке ресторана — `averageRating` и `reviewsCount`
- Flyway + тесты сервиса и контроллеров по `tests.mdc`

Вопросы до плана: оценка или оценка+текст; один отзыв навсегда или на день; нужен ли голос «сегодня»; `userId` из тела или из JWT; средний рейтинг в `RestaurantResponse` или отдельный эндпоинт.

### 2. Контекст

Собрать пакет **до** плана. Иначе агент копирует старый `RestaurantModelMapper` (`@Component` + сервис в mapper).

| Якорь             | Что класть                                                                                                                       |
|-------------------|----------------------------------------------------------------------------------------------------------------------------------|
| `@контракт`       | `.cursor/rules/architecture-layers.mdc`, `controller`, `service`, `repository`, `tests`, `naming`, `error-handling`, `injection` |
| `@образец` CRUD   | `TagController`, `TagService`/`Impl`, `TagRepository`, `TagModelMapper`, `TagCreateRequest`                                      |
| `@образец` домена | `VoteControllerUser`, `VoteServiceImpl`, `Vote`, `V004__create-votes.sql`                                                        |
| `@entity`         | `User`, `Restaurant`, `Vote`                                                                                                     |
| `@тест`           | `TagServiceTest`, `TagControllerTest`, `VoteControllerUserTest`, `AbstractTest`, `AbstractControllerTest`, `DataBuilder`         |

Плюс `RestExceptionHandler`, `SecurityConfig`.

**Промпт**

```text
Собери контекстный пакет для <Entity>. Не пиши код.
@контракт — rules слоёв.
@образец — Tag (CRUD + static mapper) и Vote (связь user/restaurant + unique).
@entity — User, Restaurant, Vote.
@тест — Tag*Test, VoteControllerUserTest, DataBuilder.
Выпиши: какие файлы создать, какие трогать, что копировать нельзя
(RestaurantModelMapper как бин, @WebMvcTest, чужой Repository из сервиса).
```

### 3. План `[GATE]`

Режим **Plan**. Выход — таблица файлов, не «сделаем CRUD».

Типовой состав:

| Слой           | Файлы                                                                                     |
|----------------|-------------------------------------------------------------------------------------------|
| entity         | `entity/<Entity>.java`                                                                    |
| db             | `V0xx__create_<table>.sql`                                                                |
| repo           | `<Entity>Repository` — только методы сервиса; `JOIN FETCH` + `countQuery` у `Page`        |
| service        | `<Entity>Service` / `Impl`                                                                |
| web USER/ADMIN | `*ControllerUser` / `*ControllerAdmin`, `*CreateRequest` / `*UpdateRequest` / `*Response` |
| mapper         | `<Entity>ModelMapper` — final + static, как `TagModelMapper`                              |
| tests          | `*ServiceTest`, `*Controller*Test`, `DataBuilder.buildX`/`saveX`                          |

Инварианты: `id == null` → 400; not found → 404; дубль/бизнес-правило → 400; чужие сущности только через их `*Service`.

**Стоп до ОК человека:** нет списка файлов, нет ответов на вопросы шага 1, не решено, куда класть агрегаты (средний рейтинг и т.п.).

### 4. Тесты (red)

Skill **`unit-test`**. `crud-endpoint` не вызывать.

Скелет (entity, интерфейс, репозиторий, сигнатуры) — чтобы тесты компилировались. Бизнес-логики нет.

`./gradlew test --tests '*<Entity>*'` должен быть **красным**. Зелёный на этом шаге = тесты ничего не проверяют.

**Промпт**

```text
По утверждённому плану напиши только тесты <Entity>.
Skill @unit-test. Образец: @TagServiceTest @TagControllerTest @VoteControllerUserTest
Прод-код не реализовывать. Прогони тесты — они должны быть красными.
```

---

### 5. Реализация (green)

Skill **`crud-endpoint`**. Пункт про тесты: если уже есть — не трогать.

Rules важнее скилла. Mapper — static, как `TagModelMapper`. Не инжектить сервис новой сущности в чужой mapper.

**Промпт**

```text
Реализуй <Entity> так, чтобы существующие тесты стали зелёными.
Skill @crud-endpoint: слои и миграция, тесты не трогать.
Следуй .cursor/rules. Прогони ./gradlew test. Тесты не ослаблять.
```

---

### 6. Верификация

```bash
./gradlew test
```

Готово, если компиляция ок, новые и старые тесты зелёные, миграция поднимается на H2.

---

### 7. Ревью `[GATE]`

Skill **`code-review`**. Опционально Bugbot.

Править только блокеры, затем снова `./gradlew test`. Шаг 8 при открытых блокерах нельзя.

**Промпт**

```text
Ревью диффа <Entity> по .cursor/rules. Skill @code-review.
Только дифф плюс соседние вызовы. Список: блокер / замечание / можно позже.
```

---

### 8. Рефакторинг

Skill **`refactor-srp`**. Контракт (URL, статусы, JSON, тексты ошибок) не менять. Тесты не переписывать. Один запах — один шаг — `./gradlew test`.

**Промпт**

```text
Тесты зелёные. Почисти дифф <Entity> без смены поведения.
Skill @refactor-srp. Mapper — static; сервис не вызывать из mapper.
```

---

### 9. PR

Один коммит — зачем, не список файлов.

```text
feat(review): отзывы и оценки ресторанов после обеда

Пользователь оставляет одну оценку на ресторан; в карточке ресторана
видны средний рейтинг и число отзывов.
```

В теле PR: DoD, инварианты, роли, как гоняли `./gradlew test`, что сознательно не делали.
